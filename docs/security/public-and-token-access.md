# PUBLIC & TOKEN-SCOPED ACCESS
## DOC-143 — public projections, Builder sessions, share/casting-safe tokens, revocation и cache-safe access

**Статус:** Canonical / Required

---

## 1. Назначение

Документ определяет правила для всех поверхностей, доступных без Admin session: Public Site, Public Questionnaire, Public Questionnaire Builder, public media, share links, QR targets и token-scoped casting-safe resources.

> **Public access is projection-based; token access is scope-based. Neither surface can infer or retrieve hidden Admin Source, and no token may silently widen into another access class.**

---

## 2. Access classes

```text
PUBLIC
TOKEN_SCOPED
ADMIN_ONLY
```

Допускаются более точные internal subclasses, но любое externally served resource должно иметь однозначный effective class.

## 3. Public projection

Public projection содержит только явно опубликованные/разрешённые данные.

Алгоритм:

```text
load current Source
→ apply lifecycle
→ apply publication state
→ apply field/item visibility
→ apply resource access safety
→ serialize Public DTO
```

### PUB-INV-001
Public payload is allowlist projection, not full Source minus a blacklist.

## 4. Hidden-data non-disclosure

Hidden data must not appear in:

- HTML;
- RSC/JSON payload;
- API response;
- client state;
- source maps/runtime debug payload;
- public Search index;
- public cache;
- analytics event generated by public client.

## 5. Public Questionnaire

Public Questionnaire endpoint resolves only published primary/selected public QuestionnaireRevision. Historical revision access requires explicit policy.

PDF/public HTML use immutable revision/snapshot and public-safe links/media only.

## 6. Public Builder

Builder uses a dedicated server-created eligibility projection.

Browser may receive only fields required for:

- template selection;
- section/item selection;
- preview;
- generation.

It never receives Admin-only alternatives.

## 7. Builder session

Suggested properties:

```text
opaque_id
profile_id
created_at
expires_at
version
anti_abuse metadata minimized
```

Builder session is temporary, opaque, bounded and not an Admin identity.

## 8. Builder tamper resistance

At Generate, server reloads/revalidates all selected item IDs. Client snapshot or checkbox state is not authority.

If item became archived/hidden/ineligible, Generate rejects/removes it according to contract; it is never leaked because old client requested it.

## 9. Share links

Application-controlled ShareLink MAY wrap a public or scoped destination for attribution/usability.

ShareLink stores target relation server-side; redirect endpoint must not accept arbitrary destination query.

```text
/share/{opaqueCode}
→ resolve stored target
→ verify active/scope
→ optional safe analytics event
→ redirect
```

### PUB-INV-002
Share tracking cannot broaden target access.

## 10. Token-scoped resources

Token MUST bind to explicit resource/scope and security policy.

Suggested token record:

```text
id
token_hash
resource_type
resource_id
scope
purpose
created_at
expires_at?
revoked_at?
created_by
```

Raw high-entropy token is shown/embedded only as needed and not stored in logs.

## 11. Token hashing

Where server only needs equality verification, store cryptographic token hash rather than plaintext.

Do not use fast unsalted user-password-style semantics incorrectly; high-entropy random token hash is sufficient with suitable cryptographic hash/HMAC design.

## 12. Token entropy

Opaque token must be generated by CSPRNG with sufficient entropy to prevent guessing/enumeration.

Human-readable sequential IDs are not token credentials.

## 13. Token scope

Examples:

```text
READ_QUESTIONNAIRE_REVISION
READ_GENERATED_BUILDER_ARTIFACT
READ_CASTING_SAFE_MEDIA
READ_SHARE_RESOURCE
```

Avoid profile-wide generic `READ_ALL_PRIVATE` tokens.

## 14. Expiry

Token lifetime should match intended business use.

- Public stable resource may need no token.
- Temporary casting access should normally be bounded/revocable.
- Ephemeral storage URL should not be embedded in durable PDF as substitute for application token.

## 15. Revocation

Revocation takes effect at application resolver and cache layers.

A revoked token must fail even if artifact bytes still exist in storage.

### PUB-INV-003
Historical snapshot immutability does not override current access revocation.

## 16. Physical distribution limit

Already downloaded/printed PDF cannot be remotely erased. Documentation/UI must not promise impossible recall.

## 17. Token in URL

When token is necessarily part of URL:

- use HTTPS;
- never log full URL in application analytics;
- set appropriate Referrer-Policy;
- avoid third-party resources on sensitive token pages that can receive referrer;
- avoid placing token in page title/DOM text unnecessarily.

## 18. Referrer protection

Token-scoped page should apply restrictive referrer policy such as no-referrer/same-origin as design requires.

## 19. Cache policy

Public immutable resources MAY be publicly cacheable.

Token-scoped resources must not enter shared public cache keyed only by path/entity.

Options:

- private/no-store response;
- cache partitioned by authorization context;
- resolver access check before protected bytes.

### PUB-INV-004
Public and token-scoped cache entries are never interchangeable.

## 20. Media access

Private originals remain private. Public/tokenized resolver selects allowed derivative/original according to media policy.

No endpoint accepts user-provided filesystem path.

## 21. QR

QR target must match access class.

Public QR → public stable URL.

Casting-safe QR → deliberate scoped application URL, with token protected from logs/cache.

Admin/raw-storage URL never allowed.

## 22. Search

Public Search indexes only Public projection.

Token-scoped resources are not globally indexed/searchable.

Admin Search remains separate.

## 23. SEO

Token-scoped pages/artifacts must be non-indexable where they have web render surfaces.

Public pages follow SEO policy.

## 24. Error semantics

For anonymous probing, avoid revealing hidden entity existence.

Examples:

```text
404/invalid resource
```

may be preferable to distinct “exists but private” response where disclosure matters.

## 25. Rate limiting

Apply to:

- repeated invalid token attempts;
- ShareLink resolver abuse;
- Builder creation/generation;
- public Feedback where applicable.

Do not rate-limit normal media streaming so aggressively that legitimate usage fails; use endpoint-specific policy.

## 26. Token rotation

If access token is suspected compromised, create new token and revoke old. Do not mutate old historical token string in-place conceptually.

## 27. Token provenance

Audit creation/revocation of sensitive scoped tokens, but never include raw token in Audit.

## 28. Builder generation artifacts

GenerationSnapshot freezes semantic content. Access policy to its artifact is separate metadata and can later revoke external read without rewriting snapshot.

## 29. Analytics

Public analytics may store ShareLink ID/source attribution, never raw private token.

Exact QR target must not be silently replaced with analytics redirect unless ShareLink was explicitly the business target.

## 30. Third-party embeds

Token-scoped pages should avoid arbitrary third-party embeds because they can leak referrer/context. Provider embeds require explicit security review.

## 31. CSP/cache headers

Public and token-scoped responses may have different CSP/cache/referrer headers. Sensitive token page should default stricter.

## 32. Public write boundaries

Public caller may only perform explicitly supported commands:

```text
SubmitFeedback
Builder session operations
Analytics ingestion
```

These commands do not grant subsequent read access to Admin record unless separately designed.

Example: Feedback submission is write-only; caller cannot GET Feedback by returned UUID.

## 33. Anti-patterns

Forbidden:

1. Full Admin Source hydrated to public page.
2. Builder receives hidden contacts then UI filters.
3. Sequential token codes.
4. UUID used as private access credential.
5. Token grants profile-wide Admin read.
6. Revoked token still works via CDN/shared cache.
7. Token appears in analytics/referrer logs.
8. Tokenized page loads arbitrary third-party scripts/images.
9. Share redirect takes `?url=` from client.
10. QR encodes Admin URL.
11. Public Search indexes token-scoped content.
12. Feedback submit response enables GET by Feedback ID.
13. Builder session persists forever.
14. Browser controls Builder eligibility.
15. Current security revocation ignored because snapshot is immutable.

## 34. E2E cases

- hidden Profile/Contact/Skill absent from public payload;
- Builder forged hidden item ID rejected without leak;
- Builder session expires;
- token with wrong resource denied;
- token with wrong scope denied;
- expired/revoked token denied;
- public resource works without Admin session;
- private artifact not served through public cache;
- ShareLink cannot redirect to client-supplied attacker URL;
- token absent from analytics/log output;
- scoped page not indexed;
- Feedback UUID not readable publicly;
- revoked token remains denied after cache hit attempt;
- QR target matches intended access class;
- downloaded artifact revocation limitation accurately represented.

## 35. Acceptance criteria

`AC-PUB-001` Public data is produced by allowlisted projection.  
`AC-PUB-002` Hidden fields/items never reach public/Builder serialization.  
`AC-PUB-003` Builder session is opaque, expiring and non-Admin.  
`AC-PUB-004` Builder Generate revalidates current Source eligibility.  
`AC-PUB-005` Share redirect uses stored target, not arbitrary URL.  
`AC-PUB-006` Scoped tokens are high-entropy, purpose/resource bound and revocable.  
`AC-PUB-007` Token-scoped cache cannot leak into public cache.  
`AC-PUB-008` Tokens are excluded from logs/analytics/referrer leakage.  
`AC-PUB-009` Revocation can block future application access despite immutable snapshots.  
`AC-PUB-010` Token-scoped resources are absent from public Search/SEO.  
`AC-PUB-011` Public write endpoints do not imply public read access to resulting private records.  
`AC-PUB-012` E2E coverage proves projection, Builder, token, cache, share and revoke boundaries.

---

## 36. Финальная доктрина

> **Public surfaces expose only explicit public projections; token surfaces expose only an explicit scoped resource. Builder sessions, share links and casting-safe tokens are narrow capabilities with expiration/revocation and can never elevate to Admin. Cache, Search, QR, analytics and media delivery preserve the same access classification end-to-end.**
