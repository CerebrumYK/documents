# ТЕХНИЧЕСКОЕ ЗАДАНИЕ

## Развитие сайта актрисы: портфолио, эмоциональный ряд, актёрские анкеты, контакты, курсы, кастинги, обратная связь и управление оформлением

---

# 1. Общие положения

## 1.1. Назначение документа

Настоящее техническое задание определяет требования к развитию публичного сайта актрисы и закрытой административной панели.

В рамках проекта необходимо реализовать:

1. Самостоятельный раздел основного актёрского портфолио.
2. Самостоятельный раздел эмоционального портфолио.
3. Конструктор эмоционального ряда.
4. Отделение эмоционального портфолио от проектов.
5. Отделение курсов и тренингов от проектов.
6. Несколько типов актёрских анкет.
7. Индивидуальное управление составом каждой анкеты.
8. Индивидуальные параметры формирования PDF.
9. Выбор основной анкеты для публикации на сайте.
10. Выбор варианта анкеты при скачивании PDF.
11. Единый справочник контактов.
12. Публичный раздел «Контакты».
13. Форму обратной связи.
14. Учёт входящих обращений в административной панели.
15. Уведомления о новых обращениях в административной панели.
16. Уведомления о новых обращениях через WhatsApp.
17. Отдельный раздел «Кастинги».
18. Анализ требований кастинга.
19. Подготовку рекомендаций по составу анкеты под конкретный кастинг.
20. Создание черновой кастинговой анкеты по подтверждённым рекомендациям.
21. Управление визуальным оформлением сайта по текстовому описанию.
22. Предварительный просмотр, версионирование и откат оформления.

## 1.2. Основные принципы

При реализации должны соблюдаться следующие принципы:

* каждый функциональный раздел имеет самостоятельную модель данных;
* проекты, портфолио, эмоциональные материалы, обучение и кастинги не смешиваются;
* один исходный медиафайл хранится один раз;
* повторное использование файла выполняется посредством связей;
* исходные фотографии сохраняются без изменения;
* производные изображения создаются отдельно;
* внешность актрисы не изменяется;
* публикация выполняется только после явного действия администратора;
* личные контакты не публикуются автоматически;
* параметры каждого варианта анкеты хранятся независимо;
* HTML и PDF одного варианта анкеты формируются из одного состава данных;
* рекомендации по кастингу не являются подтверждёнными фактами без проверки администратора;
* созданная по рекомендациям анкета сохраняется как черновик;
* обращение сначала сохраняется в базе данных и только затем отправляются уведомления;
* ошибка внешнего уведомления не должна приводить к потере обращения;
* данные одного профиля не могут быть связаны с материалами другого профиля;
* изменение оформления сайта не должно изменять содержимое, контакты, анкеты, проекты или права доступа.

## 1.3. Термины

### Портфолио

Самостоятельный набор постановочных фотографий и фотографий, демонстрирующих внешность актрисы.

### Эмоциональное портфолио

Полный набор оригинальных фотографий одной эмоциональной съёмки.

### Эмоциональный ряд

Единое составное изображение, сформированное из кропнутых фотографий эмоционального портфолио.

### Проект

Фильм, сериал, спектакль, реклама, озвучивание, дубляж или другая профессиональная работа актрисы.

### Курс или тренинг

Обучение, мастер-класс, интенсив, лаборатория, семинар, школа или другая образовательная активность.

### Вариант анкеты

Отдельная конфигурация актёрской анкеты с собственным назначением, составом, порядком разделов, настройками публикации и параметрами PDF.

### Кастинг

Входящий набор требований к роли или проекту, для которого может быть создана отдельная анкета.

### Обращение

Сообщение, отправленное посетителем через публичную форму обратной связи.

### Тема сайта

Набор цветовых, композиционных и визуальных параметров публичного сайта.

* просматривать профиль;

* отправлять предложение, приглашение на кастинг, вопрос или комментарий через форму обратной связи.

# 5. Эмоциональное портфолио

## 5.1. Назначение

Эмоциональное портфолио предназначено для хранения полного набора фотографий, демонстрирующих эмоциональный диапазон актрисы.

Эмоциональное портфолио должно быть самостоятельной сущностью и отдельным подразделом актёрской анкеты.

Оно не должно относиться к:

* проектам;
* ролям;
* постановкам;
* курсам;
* тренингам;
* основному портфолио.

## 5.2. Поля эмоционального портфолио

Карточка должна содержать:

* внутренний идентификатор;
* название съёмки;
* обязательную дату съёмки;
* необязательное место съёмки;
* необязательное описание;
* фотографа или студию;
* статус;
* порядок отображения;
* список фотографий;
* список созданных эмоциональных рядов;
* дату создания;
* дату последнего изменения.

## 5.3. Статусы

Должны поддерживаться:

* черновик;
* готово;
* опубликовано;
* архив.

Архивная запись не отображается на публичном сайте.

## 5.4. Дата съёмки

Дата съёмки является обязательным полем.

Без даты съёмки нельзя:

* опубликовать эмоциональное портфолио;
* завершить эмоциональный ряд;
* включить эмоциональный ряд в анкету;
* опубликовать анкету с этим рядом;
* разрешить публичное скачивание PDF с этим рядом.

Дата должна отображаться:

* в административной панели;
* на публичной странице эмоционального портфолио;
* в профиле;
* под эмоциональным рядом;
* в HTML-версии анкеты;
* в PDF-версии анкеты.

## 5.5. Фотографии эмоционального портфолио

Для каждой фотографии должны храниться:

* идентификатор;
* ссылка на неизменяемый оригинал;
* исходное имя файла;
* название;
* отображаемая эмоция;
* подпись;
* альтернативный текст;
* порядок;
* статус публикации;
* дата добавления;
* дата изменения.

Одна фотография может использоваться в нескольких эмоциональных рядах без создания копии оригинального файла.

## 5.6. Допустимая обработка

Разрешаются:

* выбор области кадрирования;
* масштабирование внутри исходного изображения;
* перемещение фотографии внутри кадра;
* обрезка краёв;
* ручной поворот при неправильной ориентации;
* создание уменьшенной версии;
* создание версии для сайта;
* создание версии для PDF.

## 5.7. Запрещённая обработка

Запрещаются:

* изменение лица;
* изменение мимики;
* изменение формы глаз, носа, губ или головы;
* изменение причёски;
* изменение возраста;
* изменение фигуры;
* изменение цвета кожи;
* удаление или добавление элементов внешности;
* замена одежды;
* замена фона исходной фотографии;
* дорисовывание границ изображения;
* добавление предметов;
* удаление предметов;
* синтетическое расширение фотографии;
* растягивание изображения;
* изменение пропорций;
* использование фотографий, отсутствующих среди загруженных оригиналов;
* объединение частей нескольких фотографий.

## 5.8. Публичная страница

Публичная страница эмоционального портфолио должна содержать:

* название съёмки;
* дату съёмки;
* описание;
* опубликованные фотографии;
* подписи эмоций;
* увеличенный просмотр;
* опубликованные эмоциональные ряды;
* ссылку на актуальную актёрскую анкету.

# 6. Эмоциональный ряд

## 6.1. Назначение

Эмоциональный ряд является отдельным составным изображением, сформированным из фотографий одного эмоционального портфолио.

Необходимо разделять:

* эмоциональное портфолио — полный набор оригинальных фотографий;
* эмоциональный ряд — выбранную сетку из кропнутых фотографий.

## 6.2. Размеры сетки

Должны поддерживаться следующие размеры:

* 1×2;
* 1×3;
* 1×4;
* 2×2;
* 2×3;
* 2×4;
* 3×2;
* 3×3;
* 3×4;
* 4×2;
* 4×3;
* 4×4.

Количество выбранных фотографий должно точно соответствовать количеству ячеек.

## 6.3. Редактор сетки

Редактор должен позволять:

* выбрать исходное эмоциональное портфолио;
* выбрать размер сетки;
* назначить фотографию в каждую ячейку;
* заменить фотографию;
* удалить фотографию из ячейки;
* менять ячейки местами;
* использовать перетаскивание;
* менять масштаб изображения;
* перемещать изображение внутри ячейки;
* сбрасывать кадрирование;
* просматривать итоговую сетку;
* сохранять черновик;
* завершать формирование;
* дублировать существующий ряд;
* создавать несколько рядов из одной съёмки;
* удалять ряд без удаления исходных фотографий.

## 6.4. Требование крупного плана

В каждой ячейке должно использоваться крупноплановое изображение лица.

Лицо модели должно занимать не менее 90% полезной площади изображения в ячейке.

При этом:

* внешность модели не изменяется;
* лицо остаётся узнаваемым;
* пропорции не искажаются;
* фотография не растягивается;
* дополнительные детали не добавляются;
* не используется генеративное расширение;
* не используются части других фотографий;
* не допускается кадрирование, исключающее ключевые индивидуальные черты лица.

## 6.5. Проверка крупного плана

Система должна визуально показывать заполненность лица в ячейке.

Для каждой ячейки должен храниться статус:

* не проверено;
* требует корректировки;
* подтверждено.

Завершение ряда блокируется, если хотя бы одна ячейка не подтверждена.

Окончательное подтверждение выполняется администратором.

## 6.6. Параметры кадрирования

Для каждой ячейки должны сохраняться:

* идентификатор исходной фотографии;
* номер ячейки;
* координаты области кадрирования;
* масштаб;
* смещение по горизонтали;
* смещение по вертикали;
* поворот;
* статус проверки;
* дата подтверждения;
* пользователь, подтвердивший кадрирование.

## 6.7. Формируемые версии

После завершения должны создаваться:

* качественная составная версия;
* версия для публичного сайта;
* версия для PDF;
* миниатюра для административной панели.

## 6.8. Требования к результату

Сетка должна иметь:

* одинаковые размеры ячеек;
* одинаковые внутренние отступы;
* одинаковую геометрию;
* единый стиль разделителей;
* отсутствие наложения фотографий;
* отсутствие деформации;
* достаточное разрешение для печати.

## 6.9. Поля ряда

Ряд должен содержать:

* идентификатор;
* название;
* исходное эмоциональное портфолио;
* дату съёмки;
* размер сетки;
* порядок;
* статус;
* признак основного ряда;
* признак публикации;
* дату создания;
* дату изменения.

## 6.10. Основной ряд

Для одной съёмки может существовать несколько рядов.

Одновременно основным может быть только один ряд.

Назначение основного ряда не должно автоматически включать его во все варианты анкет.

# 7. Эмоциональный ряд в актёрской анкете

## 7.1. Отдельный подраздел

Эмоциональное портфолио и эмоциональный ряд должны быть отдельным подразделом анкеты и не должны смешиваться с проектами.

## 7.2. Состав блока

В анкету включаются только:

* единое изображение эмоционального ряда;
* дата съёмки;
* ссылка на полное эмоциональное портфолио.

Отдельные фотографии эмоционального портфолио в PDF и HTML анкеты не включаются.

## 7.3. Подпись

Под изображением должна отображаться подпись:

«Эмоциональный ряд. Дата съёмки: [дата]».

Подпись должна локализоваться в зависимости от языка анкеты.

## 7.4. Ссылка

Под сеткой должна отображаться кликабельная ссылка:

«Открыть полное эмоциональное портфолио».

Ссылка должна вести на публичную страницу соответствующей съёмки.

## 7.5. Настройка блока

Для каждого варианта анкеты администратор должен иметь возможность:

* включить блок;
* отключить блок;
* выбрать конкретный ряд;
* просмотреть изображение;
* увидеть дату;
* проверить ссылку;
* изменить положение блока.

---

# 8. Основное актёрское портфолио

## 8.1. Назначение

Раздел «Портфолио» предназначен для постановочных фотографий и фотографий, демонстрирующих внешность актрисы.

Раздел должен быть независим от:

* проектов;
* эмоционального портфолио;
* эмоционального ряда;
* ролей;
* курсов;
* тренингов.

## 8.2. Типы фотографий

Поддерживаются:

* в полный рост;
* крупный план;
* поясной портрет;
* профиль;
* три четверти;
* постановочная фотография;
* фотография внешности;
* дополнительный материал;
* другое.

## 8.3. Поля фотографии

Для фотографии должны храниться:

* идентификатор;
* оригинальный файл;
* тип;
* название;
* подпись;
* альтернативный текст;
* дата съёмки;
* фотограф или студия;
* порядок;
* статус публикации;
* признак основной фотографии в полный рост;
* признак основной фотографии крупным планом;
* признак доступности для анкет;
* дата создания;
* дата изменения.

## 8.4. Обязательные фотографии анкеты

Для готовой актёрской анкеты необходимы:

1. Одна фотография в полный рост.
2. Одна фотография крупным планом.

Обе фотографии должны выбираться исключительно из раздела «Портфолио».

Нельзя выбрать обязательную фотографию непосредственно:

* из проекта;
* из эмоционального портфолио;
* из эмоционального ряда;
* из курса;
* из общей медиатеки без регистрации фотографии в портфолио.

## 8.5. Основные назначения

Для профиля одновременно могут быть назначены:

* одна основная фотография в полный рост;
* одна основная фотография крупным планом.

Для отдельного варианта анкеты допускается переопределение этих фотографий.

## 8.6. Дополнительные материалы анкеты

Для каждой фотографии должен быть доступен признак:

«Разрешить использование в дополнительных материалах анкеты».

В редакторе конкретной анкеты должны поддерживаться:

* выбор дополнительных фотографий;
* исключение отдельных фотографий;
* изменение порядка;
* ограничение максимального количества;
* предварительный просмотр.

Основные фотографии не должны зависеть от блока дополнительных материалов.

## 8.7. Публичная страница

Публичный раздел должен поддерживать:

* фильтрацию по типам;
* увеличенный просмотр;
* подписи;
* даты съёмки;
* сохранение исходных пропорций;
* сортировку;
* адаптивное отображение.

---

# 9. Видео, аудио и ссылки

## 9.1. Состав блока

Блок анкеты должен состоять из:

1. Видео.
2. Аудио.
3. Внешних ссылок.

## 9.2. Медиа

Для конкретного варианта анкеты администратор должен иметь возможность выбрать:

* видеовизитку;
* дополнительные видео;
* аудиовизитку;
* голосовые записи;
* другие аудиоматериалы.

## 9.3. Таблица ссылок

Редактор ссылок должен содержать три видимых столбца:

1. Номер ссылки.
2. Описание ссылки.
3. Сама ссылка.

## 9.4. Поля ссылки

Для каждой ссылки должны храниться:

* идентификатор;
* номер;
* описание;
* полный URL;
* порядок;
* статус активности;
* признак использования по умолчанию;
* дата создания;
* дата изменения.

## 9.5. Действия

Администратор должен иметь возможность:

* добавить строку;
* изменить описание;
* изменить URL;
* удалить строку;
* изменить порядок;
* открыть ссылку для проверки;
* включить ссылку в конкретную анкету;
* исключить ссылку из конкретной анкеты.

Номер назначается автоматически в соответствии с текущим порядком.

## 9.6. Проверка

Система должна:

* проверять формат URL;
* блокировать сохранение некорректных адресов;
* требовать описание;
* не включать неактивные ссылки;
* показывать понятное сообщение об ошибке.

## 9.7. Отображение

В HTML и PDF ссылки должны отображаться таблицей:

| № | Описание | Ссылка |
| - | -------- | ------ |

Ссылки должны быть кликабельными.

Длинные адреса не должны выходить за границы страницы.

# 10. Единый справочник контактов

## 10.1. Назначение

Должен быть реализован единый справочник контактов профиля.

Он используется:

* в актёрских анкетах;
* на публичной странице контактов;
* в кнопках быстрой связи;
* в кастинговых вариантах анкеты.

## 10.2. Типы контактов

Поддерживаются:

1. Сотовый телефон для связи.
2. Сотовый телефон мамы.
3. Сотовый телефон папы.
4. WhatsApp.
5. Telegram.
6. Instagram.
7. TikTok.
8. YouTube.
9. Другое.

## 10.3. Поля контакта

Для контакта должны храниться:

* идентификатор;
* тип;
* пользовательское название;
* значение;
* URL;
* иконка;
* подпись;
* порядок;
* статус активности;
* признак основного контакта;
* показывать в анкетах по умолчанию;
* показывать на публичном сайте;
* дата создания;
* дата изменения.

## 10.4. Независимые параметры

Должны использоваться отдельные признаки:

* показывать в анкетах по умолчанию;
* показывать на сайте;
* использовать как основной способ связи.

Публикация контакта на сайте не должна автоматически включать его во все анкеты.

Включение контакта в анкету не должно автоматически публиковать его на сайте.

## 10.5. Контакты родителей

Телефоны родителей:

* хранятся отдельно;
* публикуются отдельно;
* не подменяют основной телефон;
* не включаются автоматически;
* имеют понятные подписи;
* не должны присутствовать в публичном коде при отключении.

## 10.6. Тип «Другое»

Для типа «Другое» обязательны:

* пользовательское название;
* контактные данные;
* URL или правило отображения, если переход предусмотрен.

# 11. Блок «Контакты» в анкете

## 11.1. Выбор контактов

Для каждого контакта должен отображаться отдельный чекбокс:

«Включить в анкету».

Выбор должен выполняться отдельно для каждого варианта анкеты.

## 11.2. Отображение

Для каждого типа контакта вместо полного текстового названия должна использоваться соответствующая иконка.

Контакты должны располагаться максимально компактно:

* на широком экране — не более трёх столбцов;
* на среднем экране — не более двух;
* на мобильном экране — один столбец.

Выключенные контакты не должны создавать пустые ячейки.

## 11.3. Кликабельность

Должны поддерживаться:

* телефон — ссылка для звонка;
* WhatsApp — открытие диалога;
* Telegram — открытие профиля или диалога;
* Instagram — открытие профиля;
* TikTok — открытие профиля;
* YouTube — открытие канала;
* другое — открытие заданного URL.

Кликабельность должна сохраняться в PDF.

## 11.4. Конфиденциальность

Контакт, не включённый в конкретную анкету, не должен:

* присутствовать в HTML;
* присутствовать в PDF;
* присутствовать в клиентских данных страницы;
* присутствовать в метаданных документа.

---

# 12. Публичный раздел «Контакты»

## 12.1. Назначение

Раздел предназначен для быстрой связи с актрисой или её законными представителями.

## 12.2. Состав страницы

Страница должна содержать:

* заголовок;
* краткий текст;
* основной способ связи;
* сетку опубликованных контактов;
* социальные сети;
* блок законных представителей, если он включён;
* форму обратной связи.

## 12.3. Основной контакт

Один активный контакт может быть назначен основным.

Он используется:

* в кнопке «Связаться»;
* в профиле;
* в мобильной версии;
* в верхней части страницы контактов.

## 12.4. Быстрые действия

Поддерживаются:

* телефон — набор номера;
* WhatsApp — открытие диалога;
* Telegram — открытие профиля;
* Instagram — открытие профиля;
* TikTok — открытие профиля;
* YouTube — открытие канала;
* другое — открытие URL или отображение значения.

## 12.5. Иконки и доступность

Для каждого типа должна использоваться иконка.

Для вспомогательных средств обязательно текстовое описание.

## 12.6. Компоновка

* широкий экран — до трёх столбцов;
* средний экран — до двух;
* мобильный экран — один столбец.

## 12.7. Точки доступа

Ссылка на раздел должна присутствовать:

* в основном меню;
* в подвале;
* в профиле;
* рядом с актёрской анкетой;
* в кнопке «Связаться».

## 12.8. Конфиденциальность

Закрытый контакт не должен присутствовать:

* в HTML;
* в клиентских данных;
* в публичном API;
* в метаданных;
* в скрытых элементах;
* в поисковой индексации.

# 13. Курсы и тренинги

## 13.1. Назначение

Курсы и тренинги должны быть самостоятельным разделом.

Они не должны храниться как проекты типа «Другое».

## 13.2. Типы

Поддерживаются:

* актёрский курс;
* тренинг;
* мастер-класс;
* интенсив;
* лаборатория;
* семинар;
* школа;
* повышение квалификации;
* другое обучение.

## 13.3. Поля записи

Запись должна содержать:

* идентификатор;
* название;
* тип;
* организатора;
* преподавателя или наставника;
* дату начала;
* дату окончания;
* возможность указать одну дату;
* признак продолжающегося обучения;
* формат;
* место;
* описание;
* полученные навыки;
* сертификаты;
* подтверждающие документы;
* обложку;
* фотографии;
* видео;
* ссылки;
* статус;
* порядок;
* дату создания;
* дату изменения.

## 13.4. Действия

Поддерживаются:

* создание;
* редактирование;
* дублирование;
* публикация;
* снятие с публикации;
* архивирование;
* удаление;
* сортировка;
* привязка сертификатов;
* привязка медиа;
* предварительный просмотр.

## 13.5. Публичная страница

На публичной странице отображаются:

* название;
* тип;
* организатор;
* преподаватель;
* период;
* формат;
* место;
* описание;
* полученные навыки;
* разрешённые документы;
* разрешённые материалы.

## 13.6. Исключение из проектов

Курсы не должны отображаться:

* в проектах;
* в фильтрах проектов;
* в ролевом портфолио;
* в хронологии постановок;
* в счётчиках проектов.

# 14. Перенос существующих курсов

## 14.1. Назначение

Необходимо перенести записи об обучении, ранее созданные как проекты типа «Другое».

## 14.2. Переносимые данные

Сохраняются:

* название;
* описание;
* даты;
* статус;
* порядок;
* сертификаты;
* достижения;
* фотографии;
* видео;
* документы;
* ссылки.

## 14.3. Файлы

Физические копии файлов повторно не создаются.

## 14.4. Порядок переноса

1. Предварительный просмотр.
2. Выбор данных.
3. Создание записи курса.
4. Перенос связей.
5. Проверка результата.
6. Подтверждение администратора.
7. Исключение старой записи из проектов.
8. Архивирование исходной записи.

## 14.5. Защита от дублирования

Повторный запуск переноса не должен создавать второй курс.

# 15. Варианты актёрских анкет

## 15.1. Назначение

Для одного профиля должно поддерживаться несколько независимых вариантов актёрской анкеты.

## 15.2. Базовые типы

1. Компактная.
2. Расширенная.
3. Для конкретного кастинга.
4. Пользовательская.

Администратор должен иметь возможность создавать дополнительные пользовательские варианты.

## 15.3. Компактная анкета

Может содержать:

* имя;
* основные сведения;
* фотографию в полный рост;
* крупный план;
* параметры внешности;
* основные навыки;
* языки;
* видеовизитку;
* выбранные контакты;
* ключевые проекты;
* ссылки на сайт и портфолио.

## 15.4. Расширенная анкета

Может содержать:

* полную профессиональную информацию;
* обязательные фотографии;
* дополнительные фотографии;
* эмоциональный ряд;
* проекты;
* роли;
* показы;
* достижения;
* навыки;
* языки;
* курсы и тренинги;
* видео;
* аудио;
* ссылки;
* контакты.

## 15.5. Анкета для кастинга

Должна содержать:

* наименование кастинга;
* дату создания;
* срок подачи, если указан;
* название проекта, если указано;
* собственный состав разделов;
* собственные фотографии;
* собственные проекты и роли;
* собственные навыки;
* собственные контакты;
* собственное имя PDF-файла.

## 15.6. Пользовательская анкета

Администратор задаёт:

* название;
* назначение;
* описание;
* состав;
* порядок;
* параметры PDF;
* правила публикации;
* имя файла.

## 15.7. Статусы

Поддерживаются:

* черновик;
* готова;
* опубликована;
* архивная.

Архивная анкета не должна отображаться посетителям.

* проверка доступности материалов.

## 17.9. Версии настроек

Изменение готовой или опубликованной анкеты должно создавать новую редакцию.

Должны сохраняться:

* пользователь;
* дата;
* предыдущие параметры;
* новые параметры;
* возможность восстановить предыдущую редакцию как новую.

# 18. Публикация анкеты

## 18.1. Основная анкета

Администратор должен иметь возможность выбрать один основной вариант.

Он открывается:

* по кнопке «Актёрская анкета»;
* по постоянному адресу;
* из профиля;
* из основного портфолио;
* из эмоционального портфолио.

## 18.2. Смена основной анкеты

Система должна:

1. Проверить готовность.
2. Проверить материалы.
3. Проверить HTML.
4. Проверить PDF.
5. Назначить новый вариант.

Анализ запускается только после явного действия администратора.

## 21.2. Определяемые данные

Система должна выделять:

* данные отсутствуют;
* требуется ручная проверка.

## 21.5. Ограничения

Система не должна:

* придумывать опыт;
* придумывать навыки;
* придумывать роли;
* изменять возраст;
* изменять внешность;
* изменять физические параметры;
* автоматически добавлять отсутствующие сведения в профиль;
* выдавать предположение за подтверждённый факт.

Для интеграции должен использоваться официально подключённый канал WhatsApp Business или другой утверждённый владельцем сайта способ.

## 34.2. Получатели

В настройках задаются:

* включение или отключение;

* имя получателя;

## 34.3. Содержание уведомления

* информация о новом обращении;
* номер обращения;

* имя отправителя;
* организация;
* тема;

* защищённая ссылка на карточку.

Полный текст сообщения и вложения по умолчанию не отправляются.

## 34.4. Расширенный режим

* краткий фрагмент сообщения;
* срок подачи;
* название проекта;

* предпочтительный способ связи.

Перед включением должно отображаться предупреждение о передаче данных внешнему каналу.

«Новое обращение №[номер]

Тип: [тип]
Отправитель: [имя]
Организация: [организация]
Тема: [тема]
Получено: [дата и время]

Открыть: [защищённая ссылка]»

## 34.6. Защищённая ссылка

Ссылка должна:

* вести в административную панель;
* требовать авторизацию;
* не содержать персональные данные;
* открывать нужную карточку после входа.

## 34.7. Статусы WhatsApp

* ожидает отправки;
* отправляется;
* отправлено;
* доставлено, если статус доступен;
* ошибка;
* повторная отправка;
* отключено настройками.

## 34.8. Ошибка отправки

Ошибка WhatsApp:

* не отменяет сохранение обращения;
* фиксируется;
* создаёт внутреннее предупреждение;
* допускает повтор;
* не создаёт дубликат обращения.

## 34.9. Защита от дублирования

Для одного обращения и одного получателя одинаковое первичное уведомление не должно отправляться повторно.

---

# 35. Центр уведомлений

## 35.1. Содержимое

Центр уведомлений должен показывать:

* новые обращения;
* ошибки WhatsApp;
* обращения без ответственного;
* приближающиеся сроки;
* просроченные действия.

## 35.2. Индикатор

В верхней части административной панели должен отображаться счётчик непросмотренных уведомлений.

## 35.3. Состояния

* новое;
* просмотрено;
* скрыто;
* требует действия.

Нажатие должно открывать связанную запись.

---

# 36. Настройки формы обратной связи

Администратор должен иметь возможность:

* включить или отключить форму;
* изменить заголовок;
* изменить поясняющий текст;
* выбрать доступные типы обращений;
* задать обязательные поля;
* разрешить или запретить вложения;
* определить ограничения;
* изменить текст подтверждения;
* настроить внутренние уведомления;
* настроить WhatsApp-уведомления;
* определить получателей по типам обращений.

---

# 37. Период тишины WhatsApp

Должны поддерживаться режимы:

* отправлять сразу;
* не отправлять в заданный ночной период;
* отправлять после окончания периода тишины.

Обращение и внутреннее уведомление всегда создаются сразу.

---

# 38. Защита формы обратной связи

## 38.1. Меры защиты

Необходима защита от:

* массовой автоматической отправки;
* повторных запросов;
* чрезмерной частоты;
* вредоносной разметки;
* опасных файлов;
* чрезмерно больших сообщений.

## 38.2. Ограничение частоты

Должно применяться ограничение количества отправок за установленный период.

## 38.3. Скрытое проверочное поле

Допускается скрытое поле для выявления автоматической отправки.

## 38.4. Дополнительная проверка

Дополнительная проверка может включаться при подозрительной активности.

## 38.5. Нежелательные сообщения

Администратор может:

* отметить сообщение нежелательным;
* скрыть его из основного списка;
* сохранить причину;
* прекратить повторные уведомления по нему.

---

# 39. Персональные данные

## 39.1. Согласие

Перед отправкой формы требуется обязательный чекбокс согласия.

## 39.2. Минимизация

Форма не должна требовать данные, не необходимые для ответа.

## 39.3. Передача в WhatsApp

По умолчанию передаётся минимальный объём данных.

## 39.4. Срок хранения

Должен быть предусмотрен настраиваемый срок хранения обращений.

## 39.5. Удаление

Удаление требует подтверждения.

Могут удаляться:

* обращение;
* вложения;
* внутренние комментарии;
* история уведомлений.

Допускается сохранение обезличенного факта удаления.

---

# 40. ИИ-подбор визуального оформления сайта

## 40.1. Назначение

В административной панели должен быть реализован модуль, позволяющий создавать проект визуального оформления сайта на основании текстового описания.

Администратор должен иметь возможность описать:

* настроение;
* стиль;
* цветовую гамму;
* нежелательные цвета;
* степень контрастности;
* оформление обложки;
* оформление карточек;
* оформление кнопок;
* оформление заголовков;
* событие или период, для которого создаётся тема.

## 40.2. Примеры запросов

* «Сделать оформление более театральным и драматичным».
* «Создать светлое и воздушное оформление».
* «Использовать спокойную кинематографичную гамму».
* «Сделать тёплую тему для детского актёрского портфолио».
* «Создать строгую профессиональную тему для кастинг-директоров».
* «Создать временную тему под премьеру спектакля».

## 40.3. Ограничение

Текстовое описание не должно напрямую изменять публичный сайт.

Сначала должен создаваться редактируемый проект темы.

# 41. Раздел «Оформление сайта»

## 41.1. Вкладки

Внутри раздела должны быть предусмотрены:

* дата публикации;

* основные цвета;

* шрифтовые параметры;

## 42.1. Формируемые параметры

## 42.3. Ручное редактирование

## 42.4. Фиксация параметров

Администратор должен иметь возможность закрепить отдельные параметры перед повторным подбором.

Закреплённые параметры не должны изменяться при повторном формировании темы.

# 43. Работа с обложкой

## 43.1. Источники

Поддерживаются:

* текущая фотография;
* фотография из портфолио;
* фотография из медиатеки;
* однотонный фон;
* градиент;
* декоративный фон без фотографии;
* сочетание фотографии и декоративного слоя.

## 43.2. Допустимые изменения

Разрешаются:

* выбор существующей фотографии;
* изменение положения;
* изменение масштаба;
* безопасное кадрирование;
* затемняющий или осветляющий слой;
* цветовой слой;
* декоративные элементы;
* изменение расположения текста.

## 43.3. Запрещённые изменения

Запрещаются:

* изменение лица;
* изменение внешности;
* изменение возраста;
* изменение мимики;
* изменение причёски;
* изменение фигуры;
* замена одежды;
* дорисовывание частей тела;
* удаление элементов внешности;
* объединение нескольких лиц;
* создание несуществующей фотографии актрисы;
* изменение исходного файла.

## 43.4. Декоративные элементы

Допускаются:

* текстуры;
* абстрактные формы;
* световые пятна;
* геометрические элементы;
* театральные мотивы;
* кинематографичные мотивы;
* цветовые градиенты.

Декоративные материалы должны храниться отдельно от оригинальных фотографий.

# 44. Проверка доступности оформления

## 44.1. Автоматическая проверка

Перед публикацией должны проверяться:

* читаемость основного текста;
* читаемость вторичного текста;
* контраст кнопок;
* контраст ссылок;
* видимость фокуса;
* различимость элементов управления;
* читаемость формы обратной связи;
* читаемость контактов;
* читаемость текста на обложке.

## 44.2. Блокирующие нарушения

Публикация темы должна блокироваться, если:

* текст неразличим на фоне;
* текст кнопки неразличим;
* ссылка визуально не отличается;
* отсутствует видимое состояние фокуса;
* форма становится нечитаемой;
* контакты становятся нечитаемыми;
* элементы управления теряются на фоне.

---

# 45. Предварительный просмотр темы

## 45.1. Обязательные страницы

Предварительный просмотр должен включать:

* главную страницу;
* профиль;
* портфолио;
* эмоциональное портфолио;
* проекты;
* курсы и тренинги;
* актёрскую анкету;
* контакты;
* форму обратной связи;
* окно выбора PDF.

## 45.2. Размеры экрана

Должны быть доступны:

* настольный компьютер;
* планшет;
* мобильное устройство.

## 45.3. Изоляция

Черновик темы не должен быть доступен обычным посетителям.

---

# 46. Публикация и версии темы

## 46.1. Статусы

* черновик;
* готова к проверке;
* опубликована;
* архивная.

## 46.2. Публикация

Публикация выполняется только после:

1. Завершения проверок.
2. Просмотра основных страниц.
3. Явного подтверждения администратора.

## 46.3. Атомарное применение

Все параметры темы должны применяться одной завершённой операцией.

## 46.4. Откат

Должна быть доступна команда:

«Вернуть предыдущую тему».

Откат восстанавливает:

* цвета;
* обложку;
* композицию;
* декоративные параметры;
* карточки;
* кнопки;
* шрифтовые параметры;
* анимации.

## 46.5. Временные темы

Для временной темы задаются:

* дата и время начала;
* дата и время окончания;
* тема, которая будет восстановлена после завершения.

---

# 47. Ограничения модуля оформления

Модуль не должен:

* публиковать тему без подтверждения;
* изменять биографию;
* изменять данные профиля;
* изменять состав портфолио;
* изменять проекты;
* изменять контакты;
* изменять анкеты;
* удалять материалы;
* изменять внешность актрисы;
* заменять оригинальные фотографии;
* изменять права доступа;
* изменять настройки безопасности;
* скрывать обязательные элементы доступности;
* скрывать форму обратной связи без отдельного решения администратора.

# 49. Миграция существующих данных

Существующие записи эмоционального портфолио, хранящиеся как проекты, должны быть перенесены в новый самостоятельный раздел.

При переносе сохраняются:

* название;
* описание;
* фотографии;
* видео;
* ссылки;
* порядок;
* статус публикации;
* связи с анкетами.

## 49.2. Курсы

Существующие проекты типа «Другое», являющиеся курсами или тренингами, переносятся в новый раздел после подтверждения администратора.

## 49.3. Обязательные фотографии

Существующие фотографии в полный рост и крупным планом должны быть зарегистрированы в разделе «Портфолио».

## 49.4. Безопасность миграции

Миграция должна:

* выполняться без удаления исходных файлов;
* сохранять связи;
* показывать предварительный результат;
* предотвращать дублирование;
* фиксировать исходную запись;
* позволять проверку до удаления или архивирования старой записи.

# 50. Проверки готовности

## 50.1. Эмоциональное портфолио

Публикация блокируется, если:

* отсутствует дата;
* отсутствуют фотографии;
* отсутствуют обязательные подписи;
* опубликованный ряд не завершён.

## 50.2. Анкета

Статус «Готова» блокируется, если:

* отсутствует фотография в полный рост;
* отсутствует крупный план;
* включён пустой блок;
* недоступен файл;
* отсутствует дата эмоционального ряда;
* ряд не подтверждён;
* включён пустой контакт;
* включена некорректная ссылка;
* PDF не формируется;
* HTML не формируется.

## 50.3. Основная анкета

Назначение блокируется, если:

* вариант не готов;
* вариант архивный;
* PDF недоступен;
* HTML содержит ошибку;
* обязательные материалы не опубликованы;
* срок доступности завершён.

## 50.4. Контакты

Публикация блокируется, если:

* отсутствует значение;
* URL некорректен;
* не указан тип;
* для типа «Другое» отсутствует название;
* основной контакт неактивен.

## 50.5. Обратная связь

Отправка блокируется, если:

* отсутствует обязательное поле;
* отсутствует контакт для ответа;
* не принято согласие;
* файл недопустим;
* превышен лимит;
* превышена допустимая частота.

## 50.6. Тема сайта

Публикация блокируется, если:

* не завершена проверка;
* нарушена читаемость;
* отсутствует видимый фокус;
* форма обратной связи нечитаема;
* контакты нечитаемы;
* черновик не был подтверждён администратором.

# 51. HTML и PDF

## 51.1. Единый состав

HTML и PDF одного варианта должны формироваться по одному набору параметров.

## 51.2. PDF

PDF должен:

* сохранять кликабельные ссылки;
* сохранять кликабельные контакты;
* включать только выбранные данные;
* включать обязательные фотографии;
* включать выбранные дополнительные фотографии;
* включать единый эмоциональный ряд;
* отображать дату съёмки;
* отображать ссылку на полное эмоциональное портфолио;
* корректно переносить длинные адреса;
* не создавать пустые страницы;
* сохранять читаемость при печати;
* не обрезать содержимое.

## 51.3. HTML

HTML должен:

* быть адаптивным;
