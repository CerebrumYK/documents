# ТЕХНИЧЕСКАЯ СПЕЦИФИКАЦИЯ РЕАЛИЗАЦИИ

## Дополнительный функционал сайта актрисы

**Статус:** готово к декомпозиции и разработке
**Назначение:** единый источник требований для разработки, тестирования и приёмки
**Принцип:** ни одна функция не считается завершённой только по наличию интерфейса — должны быть реализованы модель данных, серверная логика, валидация, права доступа, публичное представление, тесты и документация.

# 2. Обязательные архитектурные правила

## 2.1. Исходные файлы

Оригинальные медиафайлы должны быть immutable.

Ни один редактор не должен физически изменять оригинальный файл.

Для любых изменений создаются:

* метаданные преобразования;
* производная web-версия;
* производная PDF-версия;
* thumbnail;
* при необходимости master derivative.

## 2.2. Повторное использование

Если один файл используется:

* в проекте;
* в портфолио;
* в эмоциональном портфолио;
* в анкете;

файл не копируется.

Создаются отдельные связи с одним media asset.

## 2.3. Публикация

Любая новая сущность создаётся как черновик.

Запрещена автоматическая публикация:

* портфолио;
* эмоционального портфолио;
* эмоционального ряда;
* курса;
* анкеты;
* кастинговой анкеты;
* темы сайта;
* контакта.

## 2.4. Изоляция профилей

Каждая серверная операция обязана проверять:

```text
requestedEntity.profileId == currentProfile.id
```

Нельзя полагаться только на фильтрацию интерфейса.

Cross-profile relation должен отклоняться сервером.

## 2.5. Миграции

Запрещается изменять уже применённые миграции.

Каждое изменение БД оформляется новой migration.

## 2.6. Ошибки

Пользователь не должен получать:

```text
500
ForeignKeyConstraintError
Undefined is not a function
```

Интерфейс должен показывать:

```text
Не удалось сохранить фотографию.
Исходный файл больше недоступен.
Выберите другую фотографию и повторите попытку.
```

# 8. UI создания эмоционального ряда

Полный пользовательский сценарий должен выглядеть следующим образом.

## Шаг 1

Администратор открывает:

```text
Эмоциональный ряд → Создать
```

## Шаг 2

Выбирает эмоциональное портфолио.

После выбора отображаются:

* название;
* дата съёмки;
* количество доступных фотографий;
* thumbnails.

## Шаг 3

Администратор выбирает сетку.

Например:

```text
4 × 4
```

Система создаёт 16 пустых ячеек.

## Шаг 4

Администратор нажимает первую ячейку.

Открывается selector фотографий.

## Шаг 5

После выбора фотографии автоматически открывается crop editor.

## Шаг 6

В crop editor доступны:

* zoom +;
* zoom −;
* перемещение;
* центрирование;
* reset;
* preview.

## Шаг 7

Администратор формирует крупный план лица.

Целевое правило:

**около 90% полезной площади кадра должно занимать лицо модели.**

Система может подсказать предполагаемую заполненность, но окончательное подтверждение выполняется человеком.

## Шаг 8

Администратор нажимает:

```text
Подтвердить кадр
```

Статус ячейки меняется:

```text
unchecked → confirmed
```

## Шаг 9

Процесс повторяется для всех ячеек.

## Шаг 10

Кнопка:

```text
Сформировать эмоциональный ряд
```

активна только если:

```text
filledCells == rows * columns
AND every(cell.status == confirmed)
AND shootingDate != null
```

## Шаг 11

Создаются производные файлы.

## Шаг 12

Администратор получает preview и может:

* сохранить;
* изменить;
* назначить основным;
* опубликовать.

# 9. Правила изображения эмоционального ряда

Разрешено только:

```text
crop
scale
position
orientation correction
```

Запрещено:

```text
face retouch
face generation
background generation
outpainting
inpainting
body modification
hair modification
expression modification
clothes modification
object removal
object generation
```

ИИ или компьютерное зрение могут использоваться только как помощник для определения позиции лица.

Окончательное изображение должно быть построено исключительно из пикселей исходного фото после обычного геометрического crop.

---

# 10. Генерация Emotional Grid

После любого изменения:

```text
cell crop
cell source
cell order
grid dimensions
```

все производные версии должны получить статус `stale`.

Необходимо пересоздать:

```text
master
web
pdf
thumbnail
```

Рекомендуемая логика:

```text
grid.render_version += 1
```

Старые generated-файлы могут удаляться после успешного создания новых.

До завершения нового render должна продолжать использоваться последняя успешно созданная версия.


```text
[ ] Перенести
Название
Текущий тип
Описание
Дата

```

После выбора:

```text
Предварительный просмотр
```

Администратор определяет:

```text

teacher
organizer
dates
```

После подтверждения:

1. создаётся training item;
2. создаются связи;
3. файлы не копируются;
4. source project получает ссылку на migrated entity;
5. повторный migration блокируется;
6. source может быть архивирован.

# 19. Контакты конкретной анкеты

Нельзя использовать только глобальный флаг.

Нужна отдельная связь:

## `questionnaire_contact_links`

```text

```

Таким образом:

```text
Global default
        ↓
Questionnaire override
```

После этого выбор становится независимым.

# 20. Публичная страница контактов

Сервер должен запрашивать только:

```text
WHERE
profile_id = currentProfile
AND show_on_website = true
AND is_active = true
```

Запрещено:

```text
fetch all contacts → hide secret ones in React
```

Закрытые контакты вообще не должны передаваться браузеру.

# 23. Snapshot опубликованной анкеты

Публикация должна фиксировать содержимое.

Например, если после публикации изменилось:

```text
описание проекта
контакт
фотография
навык
```

ранее опубликованная revision не должна молча менять содержимое.

Для этого необходимо хранить snapshot необходимого представления внутри revision или гарантировать immutable references.

Особенно обязательно для:

```text
casting questionnaire
```

# 31. Правила PDF layout

## 31.1. Общие правила

Запрещено:

* обрезать текст за пределами страницы;
* разрывать одну строку контакта между страницами;
* оставлять заголовок блока последней строкой страницы;
* создавать пустую страницу.

## 31.2. Emotional Grid

Изображение должно:

* сохранять aspect ratio;
* не растягиваться;
* при необходимости масштабироваться целиком;
* сопровождаться датой;
* сопровождаться кликабельной ссылкой.

## 31.3. Контакты

Контактные элементы по возможности сохраняются одной группой.

Максимум три колонки.

## 31.4. Ссылки

URL может визуально сокращаться, но hyperlink должен содержать полный адрес.

## 31.5. Кириллица

PDF renderer должен гарантировать корректное отображение кириллицы и поддерживаемых языков.

# 47. Алгоритм отправки формы

```text

        ↓
Validate rate limit
        ↓
Validate files

        ↓

        ↓

        ↓
```

# 69. Конкурентное редактирование

Для основных редакторов требуется optimistic locking.

Минимальная модель:

```text
updated_at
```

или:

```text
version integer
```

При сохранении клиент передаёт ожидаемую версию.

Если объект был изменён другим пользователем:

```text

```

UI:

```text
Эта запись была изменена другим пользователем.
Обновите данные перед сохранением.
```

Запрещено молча перезаписывать новую версию старой.

# 84. Error Cases: Emotional Grid

Обязательно обработать:

### Исходная фотография удалена

```text
Grid status → invalid
Cell → needs_adjustment
Render prohibited
```

### Изменился crop

```text
derivatives → stale
```

### Изменился размер сетки

Пользователь должен получить предупреждение:

```text
Изменение размера может удалить часть текущих ячеек.
```

### Недостаточно фотографий

Не запрещать использовать одну исходную фотографию повторно только если это явно разрешено требованиями продукта.

По умолчанию UI должен предупреждать о повторе.

---

# 85. Error Cases: Questionnaire

### Published media became unavailable

Опубликованная immutable revision должна сохранять доступную snapshot-версию либо явно фиксировать ошибку доставки.

### PDF renderer unavailable

Публикация новой revision блокируется.

Существующая опубликованная revision остаётся доступной.

### Два администратора редактируют

Сработать optimistic lock.

---

# 86. Error Cases: Feedback

### WhatsApp failed

Feedback = сохранён.

### Duplicate request

Вернуть существующий public number, если безопасно распознана та же idempotent submission.

### Attachment rejected

Форма должна показать, какой именно файл отклонён.

### Rate limit

Показать понятное сообщение без раскрытия внутренних лимитов.

---

# 87. Error Cases: Theme

### AI вернул невалидную схему

Не сохранять как готовую theme revision.

Показать:

```text
Не удалось сформировать корректную тему.
```

### Fallback temporary theme удалён

Не разрешать удаление активного fallback.

### Publication failure

Текущая production theme должна остаться неизменной.
