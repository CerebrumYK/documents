# ДЕТАЛЬНОЕ ТЕХНИЧЕСКОЕ ЗАДАНИЕ

## Дополнительный функционал сайта актрисы

---

# 1. Общий принцип реализации

Все новые функции должны быть встроены в существующий сайт и административную панель без нарушения уже работающего функционала.

При реализации необходимо соблюдать следующие общие правила:

1. Не удалять существующие пользовательские данные.
2. Не изменять уже применённые миграции базы данных.
3. Все изменения схемы выполнять новыми миграциями.
4. Не создавать физические копии медиафайлов там, где достаточно связи с уже существующим материалом.
5. Оригинальные фотографии сохранять без изменений.
6. Производные изображения хранить отдельно.
7. Не публиковать новые данные автоматически.
8. Публикация всегда должна требовать явного действия администратора.
9. Все новые сущности должны быть привязаны к конкретному профилю.
10. Не допускать связи данных разных профилей.
11. Все административные действия должны проходить проверку авторизации.
12. Все публичные данные должны проходить отдельную проверку статуса публикации.
13. Новые функции должны поддерживать существующую многоязычность сайта, где это применимо.
14. Все административные интерфейсы должны быть русскоязычными.
15. Все критические операции должны иметь понятное подтверждение.
16. Пользовательские ошибки должны отображаться нормальным текстом, а не кодом внутреннего исключения.

# EPIC 1. РЕОРГАНИЗАЦИЯ СТРУКТУРЫ КОНТЕНТА

# TASK 1.1. Отделить эмоциональное портфолио от проектов

## Цель

Эмоциональное портфолио больше не должно рассматриваться как тип обычного проекта.

Оно должно стать самостоятельной сущностью профиля актрисы.

## Требуется реализовать

Создать отдельную модель данных `Emotional Portfolio`, связанную непосредственно с профилем.

Эмоциональное портфолио не должно использовать:

* тип проекта;
* роли проекта;
* показы;
* даты спектаклей;
* проектную афишу;
* проектные счётчики;
* фильтры проектов.

## Поля

Для каждого эмоционального портфолио хранить:

* ID;
* profile ID;
* название;
* дата съёмки;
* место съёмки;
* описание;
* фотограф;
* студия;
* статус;
* порядок;
* дата создания;
* дата изменения;
* дата публикации.

## Статусы

* Черновик.
* Готово.
* Опубликовано.
* Архив.

## Административный интерфейс

Создать отдельный пункт:

**Эмоциональное портфолио**

На странице должны быть:

* список съёмок;
* дата;
* количество фотографий;
* количество эмоциональных рядов;
* статус;
* кнопка создания;
* кнопка редактирования;
* кнопка публикации;
* кнопка снятия с публикации;
* кнопка архивирования.

## Публичная часть

Эмоциональные портфолио не должны отображаться в разделе «Проекты».

Должна появиться отдельная публичная страница эмоционального портфолио.

## Критерий готовности

Задача выполнена, если эмоциональное портфолио можно создать, заполнить и опубликовать без создания записи проекта.

# TASK 1.2. Мигрировать существующие эмоциональные проекты

## Цель

Перенести уже имеющиеся эмоциональные материалы в новую структуру без потери данных.

## Требуется реализовать

Создать миграционный механизм, который:

1. Найдёт существующие проекты типа «Эмоциональное портфолио».
2. Покажет администратору список найденных записей.
3. Для каждой записи покажет:

   * название;
   * описание;
   * фотографии;
   * видео;
   * дату;
   * связанные анкеты.
4. Позволит подтвердить перенос.
5. Создаст новое эмоциональное портфолио.
6. Перенесёт связи с медиа.
7. Перенесёт связанные описания.
8. Не создаст физические копии файлов.
9. Не удалит старую запись автоматически.
10. После проверки позволит архивировать старый проект.

## Критерий готовности

После миграции все эмоциональные материалы доступны из нового раздела, а исходные файлы не продублированы.

* завершить оформление портфолио;

Дата должна отображаться:

* в административной панели;

* в HTML анкеты;
* в PDF.

---

# TASK 3.2. Реализовать выбор размера сетки

## Допустимые сетки

* 1×2;
* 1×3;
* 1×4;
* 2×2;
* 2×3;
* 2×4;
* 3×2;
* 3×3;
* 3×4;
* 4×2;
* 4×3;
* 4×4.

Интерфейс должен визуально показывать будущую сетку.

После выбора размера система должна создать соответствующее количество пустых ячеек.

Например:

* 2×2 → 4 ячейки;
* 3×4 → 12 ячеек;
* 4×4 → 16 ячеек.

---

# TASK 3.3. Реализовать выбор фотографий для сетки

Для каждой ячейки пользователь должен выбрать одну фотографию из исходного эмоционального портфолио.

## Должны поддерживаться

* визуальный выбор по миниатюрам;
* поиск по имени;
* фильтрация;
* замена фотографии;
* очистка ячейки;
* drag-and-drop;
* изменение порядка.

Использование фотографии другого профиля должно блокироваться сервером.

---

# TASK 3.4. Реализовать индивидуальный кроп каждой ячейки

После выбора фотографии должен открываться редактор кадрирования.

Пользователь должен иметь возможность:

* увеличить изображение;
* уменьшить до минимального допустимого масштаба;
* двигать фотографию;
* центрировать лицо;
* сбросить изменения;
* посмотреть конечный результат.

## Сохранять

* X;
* Y;
* ширину области;
* высоту области;
* масштаб;
* смещение;
* поворот при необходимости.

Кроп должен быть обратимо редактируемым.

Оригинальная фотография не изменяется.

---

# TASK 3.5. Реализовать правило «90% лица»

## Требование

В каждой ячейке лицо модели должно занимать приблизительно 90% полезной площади изображения.

Это правило относится к композиции эмоционального ряда.

## Интерфейс

Для ячейки отображать:

* «Не проверено»;
* «Требует корректировки»;
* «Подтверждено».

Администратор должен явно подтвердить корректность каждого кадра.

## Запреты

Нельзя:

* дорисовывать отсутствующую часть лица;
* изменять черты;
* менять выражение;
* генерировать новую область;
* заменять фон;
* смешивать разные фотографии.

---

# TASK 3.6. Проверка готовности эмоционального ряда

Кнопка «Завершить» должна быть заблокирована, если:

* есть пустая ячейка;
* количество фотографий не соответствует сетке;
* отсутствует дата съёмки;
* хотя бы одна ячейка не подтверждена;
* отсутствует исходная фотография.

На странице показать список невыполненных условий.

---

# TASK 3.7. Сформировать единое изображение

После подтверждения система должна сгенерировать:

1. Master-версию высокого качества.
2. Версию для сайта.
3. Версию для PDF.
4. Миниатюру.

Все изображения должны строиться из оригинальных фотографий и сохранённых координат кропа.

## Необходимо обеспечить

* одинаковые размеры ячеек;
* одинаковые промежутки;
* отсутствие растяжения;
* отсутствие наложения;
* одинаковый формат;
* достаточное качество PDF.

---

# TASK 3.8. Поддержать несколько эмоциональных рядов

Из одной фотосессии должно быть возможно создать несколько вариантов.

Например:

* 2×3;
* 3×4;
* 4×4.

Один ряд можно назначить основным.

Назначение основным не означает автоматического включения во все анкеты.

Например:

* backgroundPrimary;
* backgroundSecondary;
* surface;
* textPrimary;
* textSecondary;
* accentPrimary;
* accentSecondary;
* link;
* buttonPrimary;
* buttonSecondary;
* border;
* focus;
* success;
* warning;
* error.

---

# TASK 24.5. Показать конкретные цвета

Для каждого token:

* цвет;
* HEX;
* назначение;
* contrast result.

---

# TASK 24.6. Ручное изменение

После ИИ все значения остаются редактируемыми.

---

# TASK 24.7. Lock параметров

Администратор должен закрепить token.

При повторном запросе закреплённый token не изменяется.

Например:

**Сохранить текущий зелёный цвет кнопок, но сделать остальные цвета теплее.**
