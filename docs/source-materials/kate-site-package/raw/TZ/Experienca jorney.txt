# CUSTOMER JOURNEY И МЕТОД 6-3-5

## Проектирование сайта актрисы вокруг реальных сценариев получения кастингов и ролей

---

# 1. Назначение

Сайт должен проектироваться не как электронная биография и не как статическая галерея фотографий.

Его основная бизнес-функция:

> **максимально быстро дать профессиональному посетителю достаточно информации для принятия решения о дальнейшем контакте с актрисой и максимально упростить следующий шаг: просмотр видео, получение анкеты, запрос дополнительных материалов или приглашение на кастинг.**

Основная логика публичного сайта:

```text
Привлечь внимание
        ↓
За несколько секунд объяснить, кто перед посетителем
        ↓
Дать возможность быстро проверить соответствие роли
        ↓
Показать профессиональные доказательства
        ↓
Убрать сомнения
        ↓
Предоставить нужный формат материалов
        ↓
Максимально упростить контакт
        ↓
Получить профессиональное обращение
        ↓
Не потерять обращение
        ↓
Подготовить материалы под конкретный кастинг
        ↓
Отследить результат
```

Оптимизация сайта должна выполняться не вокруг показателя:

> «Сколько страниц посмотрел посетитель»

а вокруг:

> **«Насколько быстро профессиональный посетитель получил необходимую информацию и выполнил полезное действие».**

---

# 2. Реалистичная модель поведения кастинг-специалиста

Современные профессиональные кастинговые профили строятся вокруг быстрого доступа к фотографии, credits, reels, skills и другим ключевым материалам. Casting Networks отдельно предусматривает быстрый high-level просмотр talent с фотографиями, credits и reels, а затем переход к расширенным assets и skills.

Spotlight также указывает, что профессиональные профили используются для поиска по таким параметрам, как skills, languages и location/base, а showreels и voice clips помогают кастинг-специалисту получить дополнительное представление о незнакомом актёре.

Отдельно важен сценарий контакта: профессиональные запросы могут касаться availability, self-tape, конкретного навыка или дополнительных video/audio materials.

Из этого следует основополагающий принцип сайта:

```text
Не заставлять кастинг-специалиста изучать сайт.

Дать ему возможность получить именно ту информацию,
которая нужна ему сейчас.
```

---

# 3. Главный принцип UX

## Минимум действий → максимум профессиональной информации → понятное следующее действие

Для каждого ключевого сценария должно существовать кратчайшее действие.

Целевые UX-правила:

```text
Посмотреть основную информацию     → без дополнительного перехода
Запустить видеовизитку             → 1 действие
Открыть портфолио                  → 1 действие
Открыть эмоциональный диапазон     → 1 действие
Открыть актёрскую анкету           → 1 действие
Скачать нужный PDF                 → максимум 2 действия
Связаться                           → максимум 2 действия
Пригласить на кастинг              → максимум 2 действия
Найти конкретный навык             → 1 поиск
```

Человек не должен сначала понимать архитектуру сайта, чтобы найти нужный материал.

---

# 4. Три уровня информации

Публичная часть должна строиться по принципу progressive disclosure.

## Уровень 1 — решение за несколько секунд

Посетитель должен сразу понять:

* кто это;
* как выглядит актриса;
* основной профессиональный профиль;
* ключевые параметры;
* ключевые навыки;
* где находится;
* какие языки знает;
* доступна ли актёрская анкета;
* где видеовизитка;
* как связаться.

## Уровень 2 — подтверждение

Если первичное впечатление подходит:

* фотографии;
* видеовизитка;
* showreel;
* эмоциональный диапазон;
* основные проекты;
* роли;
* навыки;
* языки;
* обучение.

## Уровень 3 — профессиональная детализация

Если кандидат уже рассматривается серьёзно:

* расширенная анкета;
* дополнительные фотографии;
* все проекты;
* курсы;
* достижения;
* audio;
* дополнительные ссылки;
* материалы конкретного кастинга.

---

# 5. Первый экран

Первый экран не должен быть декоративной заставкой, которую необходимо прокрутить.

Он должен одновременно работать как:

* визуальный образ;
* профессиональная карточка;
* точка входа в основные сценарии.

Рекомендуемая структура:

```text
┌────────────────────────────────────────────────────────────┐
│                                                            │
│                  ОСНОВНАЯ ФОТОГРАФИЯ                       │
│                                                            │
│  Имя Фамилия                                               │
│  Актриса                                                   │
│                                                            │
│  Краткие профессиональные параметры                        │
│  Город • Языки • Ключевые навыки                           │
│                                                            │
│  [▶ Видеовизитка]  [Актёрская анкета]  [Связаться]         │
│                                                            │
└────────────────────────────────────────────────────────────┘
```

На мобильной версии эти три действия должны оставаться доступными без сложной навигации.

---

# 6. Постоянная профессиональная панель

На публичных страницах рекомендуется использовать компактную action-панель:

```text
▶ Видео     📄 Анкета     ✉ Связаться
```

На мобильном устройстве она может быть sticky.

Она не должна занимать значительную часть экрана.

---

# 7. Метод 6-3-5 для проектирования сайта

Для проекта используется адаптация метода 6-3-5:

```text
6 персонажей
×
3 ключевые идеи/наблюдения
×
5 минут взаимодействия
=
18 независимых продуктовых выводов
```

Каждому персонажу даётся реальная профессиональная задача.

Персонаж должен получить максимум пять минут на работу с сайтом.

Если за это время задача не решается — Customer Journey считается неудачным.

---

# 24. Главная задача виртуального оператора

Владелец сайта не должен выполнять последовательность:

```text
загрузить файл
→ открыть медиатеку
→ найти файл
→ создать проект
→ заполнить поля
→ добавить в портфолио
→ обновить анкету
→ обновить PDF
→ обновить SEO
→ проверить ссылки
```

Вместо этого:

```text
Добавить материал
       ↓
Оператор анализирует
       ↓
Предлагает изменения
       ↓
Администратор подтверждает
       ↓
Система выполняет связанные операции
```

---

# 25. Journey — Virtual Operator

## 00:00–01:00

```text
Похоже на фотографии портфолио
```



* проверяет broken links;
* проверяет completeness;

# 26. 3 идеи от Persona 6

### IDEA VO-01 — Change once, propagate everywhere

Исходная информация вводится один раз.

Система сама определяет, где она используется.

### IDEA VO-02 — Draft Automation

Оператор может:

* создавать draft;
* классифицировать;
* анализировать;
* предлагать;
* пересобирать derived assets.

Но не:

* публиковать;
* придумывать факты;
* отправлять профессиональные ответы.

### IDEA VO-03 — Exception-driven administration

Администратор не должен проверять всё.

Оператор показывает только:

```text
Что нового
Что требует решения
Что сломано
Что устарело
Что можно улучшить
```

# 41. Content Freshness Operator

Отдельная функция виртуального оператора:

**Проверка актуальности профиля**

Он должен находить:

```text
старые фотографии
отсутствующие shooting dates
broken links
устаревшее видео
незаполненные проекты
просроченные casting questionnaires
неполные courses
неиспользуемые media
```

И выдавать один actionable список.

Например:

```text
Профиль: 94% готовности

Требуют внимания:

1. Фотографии портфолио сняты более N месяцев назад — проверить актуальность.
2. Ссылка «Showreel» недоступна.
3. Курс «...» не имеет даты.
4. Кастинговая анкета «...» истекает завтра.
```

Возраст фотографии сам по себе не означает, что она должна быть заменена — оператор только предлагает проверить актуальность.

# 52. Принцип проектирования конечного продукта

При принятии любого решения о новом интерфейсе необходимо задавать четыре вопроса:

### 1. Кто этим пользуется?

Конкретная persona.

Не «посмотреть страницу», а реальную задачу.

Уменьшить до разумного минимума.

```text
Contact
Casting
Audition
```

# 61. Главный критерий эффективности сайта

Сайт должен оптимизироваться не на максимальную длительность посещения.

Наоборот:

> **Профессиональный посетитель должен иметь возможность принять обоснованное решение максимально быстро.**

Успешным считается сценарий:

```text
Пришёл
→ сразу понял профиль
→ быстро нашёл доказательства
→ получил нужный документ
→ сделал профессиональный контакт
```

а не:

```text
Пришёл
→ долго искал информацию
→ открыл много страниц
→ ушёл
```

# 65. Итоговый принцип продукта

Конечная система должна быть построена вокруг двух параллельных потоков.

## Внешний поток

```text
Найти актрису
→ понять профиль
→ проверить соответствие
→ увидеть доказательства
→ получить материалы
→ связаться
→ пригласить
```

## Внутренний поток

```text
Получить материал
→ автоматически классифицировать
→ предложить изменения
→ получить подтверждение
→ обновить связанные представления
→ проверить целостность
→ отслеживать входящие возможности
→ подготовить материалы под кастинг
```

Соединение этих потоков создаёт конечную бизнес-модель сайта:

```text
КАЧЕСТВЕННЫЕ ИСХОДНЫЕ ДАННЫЕ
            ↓
     ВИРТУАЛЬНЫЙ ОПЕРАТОР
            ↓
  АКТУАЛЬНЫЙ ПРОФЕССИОНАЛЬНЫЙ
           ПРОФИЛЬ
            ↓
    ОПТИМИЗИРОВАННЫЙ CJM
            ↓
```
