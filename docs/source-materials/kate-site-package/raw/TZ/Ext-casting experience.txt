# ДОПОЛНЕНИЕ К ТЕХНИЧЕСКОМУ ЗАДАНИЮ

## Публичное представление функций и самостоятельное формирование анкеты кастинг-специалистом

---

# 137. Общий принцип: Admin → Public

Любая функция, реализуемая в административной панели и относящаяся к профессиональному публичному профилю актрисы, должна проектироваться одновременно в двух представлениях:

```text
ADMIN
Управление и подготовка данных
        ↓
PUBLIC
Профессиональное представление этих данных
```

Не допускается ситуация, когда новый функционал существует только в административной панели, но не имеет продуманного способа использования на публичном сайте.

Исключения составляют исключительно внутренние функции:

* системные настройки;
* аудит;
* внутренние комментарии;
* черновики;
* непубличные материалы кастингов;
* служебные уведомления;
* административные инструменты;
* технические журналы.

# 139. Три уровня видимости данных

Для профессиональных данных недостаточно использовать простой флаг:

```text
published = true / false
```

Необходимо разделить минимум три уровня разрешения.

Для сущностей, которые потенциально могут попадать в анкету, должны поддерживаться:

```text
show_on_public_site
allow_in_admin_questionnaires
allow_in_public_questionnaire_builder
```

## 139.1. `show_on_public_site`

Разрешает отображать элемент непосредственно на публичных страницах.

## 139.2. `allow_in_admin_questionnaires`

Разрешает администратору использовать элемент в подготовленных анкетах.

## 139.3. `allow_in_public_questionnaire_builder`

Разрешает кастинг-специалисту самостоятельно выбрать этот элемент при формировании собственной версии анкеты.

Эти параметры должны быть независимыми.

---

# 140. Пример независимости разрешений

Фотография может иметь:

```text
show_on_public_site = true
allow_in_admin_questionnaires = true
allow_in_public_questionnaire_builder = true
```

Другой материал:

```text
show_on_public_site = false
allow_in_admin_questionnaires = true
allow_in_public_questionnaire_builder = false
```

Такой материал может использоваться администратором в специальной анкете, но публичный посетитель никогда его не увидит.

---

# 141. Запрет раскрытия скрытых данных

Публичный конструктор анкеты может использовать **только те данные, которые явно разрешены для Public Questionnaire Builder**.

Нельзя:

```text
загрузить все данные профиля
→ скрыть запрещённые checkbox через UI
```

Серверный запрос должен сразу возвращать только разрешённый набор.

То есть:

```text
WHERE
profile_id = ...
AND allow_in_public_questionnaire_builder = true
AND object_status = published/available
```

---

# 142. Два вида актёрской анкеты на сайте

Публичный сайт должен поддерживать два принципиально разных сценария.

## 142.1. Готовая анкета

Анкета подготовлена администратором.

Это профессионально выверенная рекомендуемая версия.

Например:

```text
Актёрская анкета
Рекомендуемый вариант
```

CTA:

```text
Открыть
Скачать PDF
```

## 142.2. Собственная анкета кастинг-специалиста

Дополнительный CTA:

```text
Собрать анкету под свой кастинг
```

или:

```text
Сформировать свою версию
```

Кастинг-специалист самостоятельно выбирает необходимые сведения из разрешённых данных профиля.

---

# 143. Основной принцип конструктора

Кастинг-специалист не редактирует исходные данные актрисы.

Он формирует только **представление существующих опубликованных данных**.

Схема:

```text
PUBLISHED ACTOR DATA
        ↓
AVAILABLE TO PUBLIC BUILDER
        ↓
CASTING SPECIALIST SELECTION
        ↓
TEMPORARY QUESTIONNAIRE CONFIGURATION
        ↓
PREVIEW
        ↓
PDF
```

Никакие изменения не записываются обратно в профессиональный профиль.

---

# 144. Причина существования Public Questionnaire Builder

Готовая анкета администратора может:

* быть слишком подробной;
* быть слишком краткой;
* содержать сведения, незначимые для конкретного кастинга;
* не содержать материал, который важен конкретному кастинг-специалисту.

Поэтому сайт должен позволять профессиональному пользователю самостоятельно сформировать документ из опубликованных материалов.

Пример:

Кастинг-директору для одной роли нужны:

```text
Крупный план
Полный рост
Рост
Языки
Танцы
Эмоциональный ряд
Видеовизитка
2 релевантных проекта
Контакт
```

Ему не нужны:

```text
все достижения
15 проектов
полная история обучения
дополнительные фотографии
все внешние ссылки
```

Он должен получить именно краткую версию.

# 146. Сценарий кастинг-специалиста

## Шаг 1

Пользователь нажимает:

```text
Собрать анкету под свой кастинг
```

## Шаг 2

Система предлагает стартовый шаблон.

Например:

```text
○ Быстрая
○ Стандартная
○ Расширенная
○ Под конкретный кастинг
```

## Шаг 3

После выбора шаблона отображается готовая рекомендуемая структура.

Пользователь может изменить её.

## Шаг 4

Пользователь выбирает нужные блоки.

## Шаг 5

Внутри блока при необходимости выбирает конкретные элементы.

## Шаг 6

Получает live preview.

## Шаг 7

Нажимает:

```text
Сформировать PDF
```

## Шаг 8

Получает PDF только с выбранными данными.

# 153. Порядок блоков

Для упрощения работы базовый порядок должен задаваться шаблоном.

Кастинг-специалисту можно предоставить возможность:

```text
☰ drag-and-drop
```

Но это не должно быть обязательным шагом.

Если пользователь ничего не меняет, система должна сформировать корректный документ автоматически.

---

# 154. Главное UX-правило

Конструктор не должен выглядеть как редактор документов.

Профессиональный пользователь не должен заниматься:

* настройкой отступов;
* шрифтов;
* размера заголовков;
* позиционированием;
* PDF layout;
* page breaks;
* цветами.

Он выбирает только:

> **какую профессиональную информацию хочет получить.**

Всю композицию система делает автоматически.

---

# 155. Progressive Configuration

Не показывать сразу десятки настроек.

Первый экран:

```text
Какую анкету вы хотите получить?

[Быстрая]
[Стандартная]
[Расширенная]
[Под кастинг]
```

После выбора:

```text
Настроить содержимое
```

И только после этого показывать blocks.

---

# 156. Recommended Selection

У каждого шаблона часть блоков включена по умолчанию.

Например:

```text
✓ Крупный план
✓ Полный рост
✓ Основные данные
✓ Языки
✓ Видео
✓ Контакт
```

Пользователю не требуется вручную начинать с пустого документа.

---

# 157. Быстрые профессиональные пресеты

В дальнейшем можно предусмотреть:

```text
Кино / сериал
Реклама
Театр
Озвучивание
Международный кастинг
```

Каждый preset определяет рекомендованный набор блоков.

При этом никаких новых данных он не создаёт.

---

При включении или отключении блока preview должен обновляться автоматически.

Рекомендуемый desktop layout:

```text
│ НАСТРОЙКИ            │ PREVIEW                    │
│                      │                            │
│ ☑ Фото               │   Актёрская анкета        │

│ ☐ Курсы              │                            │
│ ☑ Проекты            │                            │
│                      │                            │
```

```text

   ↓
[Предпросмотр]

```

---

# 159. Temporary Questionnaire

Анкета, которую сформировал внешний пользователь, не должна становиться постоянной записью в разделе административных анкет.

По умолчанию это:

```text
Temporary Questionnaire
```

с жизненным циклом:

```text
configuration
→ preview
→ PDF render
→ temporary expiration
```

---

# 160. Публичная временная конфигурация

Минимальная техническая модель:

```text
public_questionnaire_sessions
```

Поля:

```text
id
profile_id
template_type
configuration
language
casting_name NULL
role_name NULL
expires_at
created_at
```

Запрещается сохранять скрытые данные профиля в configuration.

Configuration содержит только IDs элементов, которые были разрешены публичному builder на момент создания.

---

# 161. Срок хранения

Временная конфигурация должна иметь ограниченный TTL.

Например:

```text
несколько часов или дней
```

Конкретное значение определяется системной настройкой.

После окончания:

```text
session expired
```

PDF может удаляться в соответствии с retention policy.

---

# 162. Вариант без серверного хранения

Если архитектура позволяет, базовая конфигурация может существовать только в текущей сессии до генерации PDF.

Однако сервер всё равно обязан заново проверить все выбранные IDs перед генерацией документа.

Нельзя доверять данным браузера.

---

# 163. Server-side revalidation

При генерации:

```text
generatePublicQuestionnairePdf(configuration)
```

сервер должен для каждого выбранного объекта проверить:

```text
belongs to profile
AND published/available
AND allow_in_public_questionnaire_builder = true
```

Если материал перестал быть доступным:

```text
exclude + warning
```

либо блокировать генерацию, если это обязательный материал.

---

# 164. Обязательные блоки публичной анкеты

Чтобы кастинг-специалист случайно не сформировал бессмысленный документ, некоторые элементы шаблона могут иметь статус:

```text
Required
```

Минимально рекомендуется:

```text
Имя / идентификация актрисы
Хотя бы одна основная фотография
Ссылка на исходный профиль
```

Остальные блоки могут быть отключаемыми.

---

# 165. Контакты в Public Builder

Особенно важно разделить контактные разрешения.

Для контакта добавить:

```text
allow_in_public_questionnaire_builder
```

Только такие контакты доступны внешнему пользователю.

Например:

```text
Телефон представителя       ✓
Professional email          ✓
WhatsApp                    ✓
Личный телефон              ✗
```

Даже если личный телефон существует в админке.

---

# 166. Публичные проекты

Для проекта или project subsection также нужен параметр:

```text
allow_in_public_questionnaire_builder
```

То же относится к:

* роли;
* достижению;
* курсу;
* фотографии;
* видео;
* аудио;
* ссылке.

---

# 167. Дефолтные настройки от администратора

Администратор должен управлять не только готовой анкетой, но и доступностью данных в Public Builder.

В разделе анкеты или настроек добавить:

```text
Публичный конструктор анкеты
```

Параметры:

```text
[x] Разрешить самостоятельное формирование анкеты

Доступные шаблоны:
[x] Быстрая
[x] Стандартная
[x] Расширенная
[x] Для кастинга

Default template:
Стандартная
```

---

# 168. Admin Builder Configuration

Администратор должен иметь возможность определить для каждого шаблона:

* название;
* описание;
* включённые по умолчанию блоки;
* обязательные блоки;
* максимальное число проектов;
* максимальное число фотографий;
* максимальное число курсов;
* можно ли менять порядок;
* можно ли вводить название кастинга.

---

# 169. Ограничения размера

Чтобы внешний пользователь не создавал неразумно большой PDF, администратор должен иметь возможность задавать лимиты.

Например:

```text
Projects: max 10
Extra photos: max 8
Training: max 8
External links: max 10
```

Шаблон может иметь меньшие лимиты.

---

# 170. Умный порядок по умолчанию

После выбора элементов система автоматически должна выстроить профессионально логичный порядок.

Например:

```text
1. Имя и основные сведения
2. Крупный план
3. Полный рост
4. Параметры
5. Навыки
6. Языки
7. Эмоциональный ряд
8. Проекты
9. Обучение
10. Видео
11. Контакты
```

Внешний пользователь не обязан заниматься layout.

---

# 171. Автоматическое компактирование

Если пользователь выбрал мало данных, PDF не должен содержать пустые секции.

Если выбрано много информации, renderer должен автоматически:

* перераспределить блоки;
* применять допустимые layout;
* переносить страницы;
* сохранять читаемость;
* предотвращать пустые страницы.

---

# 172. Имя PDF

Для публично сформированного документа:

```text
{actor}_{template}_{language}.pdf
```

Для кастинга:

```text
{actor}_{casting_name}_{role}_{language}.pdf
```

Все пользовательские строки проходят filename sanitization.

---

# 173. Маркировка документа

В footer рекомендуется использовать ненавязчивый источник:

```text
Сформировано с официального актёрского профиля
kate.supremevision.org
```

Это повышает доверие к документу и позволяет получателю вернуться на актуальный сайт.

---

# 174. Дата формирования

На пользовательском PDF должна присутствовать дата генерации:

```text
Сформировано: DD.MM.YYYY
```

Это позволяет понимать актуальность выгрузки.

```text
Актуальная версия профиля
```

Это снижает проблему устаревших PDF после пересылки.

# 176. QR-код

Для PDF Public Builder следует предусмотреть QR-код, ведущий на официальный публичный профиль или на разрешённую страницу анкеты.

QR должен:

* использовать публичный HTTPS URL;
* не содержать приватных данных;
* не содержать бессрочный административный token.

Визуальное отображение QR может быть включаемой настройкой шаблона.

# 197. `generatePublicQuestionnairePdf`

Алгоритм:

```text
1. Validate session.
2. Validate expiration.
3. Load current public permissions.
4. Revalidate every selected object.
5. Remove unavailable optional objects.
6. Fail if required object disappeared.
7. Build immutable generation snapshot.
8. Render PDF.
9. Store according to retention policy.
10. Return download.
11. Record anonymous/allowed analytics event.
```

# 198. Generation Snapshot

Даже временный PDF должен формироваться из фиксированного snapshot.

Это необходимо, чтобы во время процесса:

```text
preview → render
```

данные не изменились на половине документа.

Snapshot не изменяет основной профиль.

# 199. Запрет сохранения пользовательского выбора как факта профиля


Это не означает:

```text

```

Это только выбор конкретного внешнего пользователя для конкретного документа.

# 200. Без обязательной регистрации

Public Questionnaire Builder не должен требовать создания аккаунта только ради формирования PDF.

Целевой UX:

```text
Open
→ Select
→ Generate
```

Если в будущем появятся защищённые материалы, авторизация может применяться только к таким специальным сценариям.

---

# 201. Anti-abuse

Публичная генерация PDF должна иметь:

* rate limiting;
* ограниченный TTL;
* ограничения размера документа;
* ограничения количества генераций;
* серверную validation;
* защиту от произвольных IDs;
* защиту filename;
* защиту URL;
* ограничения template configuration.

Параметры ограничения не должны мешать обычному профессиональному использованию.

---

# 202. Cache

Публичные разрешённые материалы могут кешироваться.

Но изменение visibility:

```text
allow_in_public_questionnaire_builder = false
```

должно немедленно инвалидировать соответствующий public cache.

Новая PDF generation не должна использовать запрещённый материал.

---

# 203. Что происходит с уже скачанным PDF

После скачивания пользователь имеет локальную копию.

Система не может физически изменить уже скачанный документ.

Поэтому документ должен содержать:

```text
Дата формирования
Ссылка на актуальный профиль
```

при необходимости QR.

---

# 204. Отзыв временной публичной ссылки

Если для Public Builder реализуется shareable online preview, администратор должен иметь возможность:

```text
Disable all temporary public questionnaires
```

или отключить конкретную session.

PDF, уже скачанный пользователем, естественно, отозвать невозможно.

# 213. Business Outcome

Новый Builder решает сразу несколько задач:

### Для кастинг-специалиста

Он получает только релевантную информацию.

### Для актрисы

Не требуется вручную готовить отдельный PDF для каждого первого контакта.

### Для администратора

Не требуется угадывать единственный идеальный формат анкеты.

### Для маркетинга

Посетитель дольше остаётся в профессиональном funnel не за счёт искусственного удержания, а потому что получает инструмент.

### Для кастинга

Снижается friction между:

```text
интерес
```

и:

```text
получение подходящих материалов
```

# 214. Главный принцип конечной логики

После этого уточнения система должна строиться вокруг модели:

```text
ОДИН ДОСТОВЕРНЫЙ ПРОФИЛЬ
          ↓
   ПУБЛИЧНЫЕ ДАННЫЕ
          ↓
 ┌────────┴─────────────┐
 ↓                      ↓
Кураторская        Пользовательская
анкета             выборка Casting
администратора     Specialist
 ↓                      ↓
PDF                Custom PDF
 └────────┬─────────────┘
          ↓
    PROFESSIONAL CTA
          ↓
       CASTING
```

Администратор отвечает за:

* достоверность;
* полноту;
* разрешение данных;
* рекомендуемые шаблоны;
* профессиональную презентацию.

Кастинг-специалист получает свободу:

* выбрать необходимый объём;
* исключить лишнее;
* добавить релевантные опубликованные сведения;
* сформировать собственный PDF.

При этом он **никогда не получает доступ к административным или закрытым данным и никогда не изменяет исходный профиль**.

# 215. Новые обязательные критерии приёмки

1. Все профессиональные функции имеют продуманное публичное представление.
2. Публичная часть не является вторичной копией админ-панели.
3. На сайте существует готовая рекомендованная анкета администратора.
4. На сайте существует CTA «Собрать анкету».
5. Public Builder не требует обязательной регистрации.
6. Пользователь начинает с готового шаблона.
7. Поддерживаются Quick, Standard, Extended и Casting templates.
8. Пользователь может включать и отключать блоки.
9. Для поддерживаемых блоков можно выбирать конкретные элементы.
10. Пользователь может выбрать проекты.
11. Пользователь может выбрать навыки.
12. Пользователь может выбрать языки.
13. Пользователь может выбрать курсы.
14. Пользователь может выбрать дополнительные фотографии.
15. Пользователь может выбрать эмоциональный ряд.
16. Пользователь может выбрать разрешённые видео и ссылки.
17. Пользователь видит только материалы, разрешённые Public Builder.
18. Скрытые материалы не передаются браузеру.
19. Сервер повторно проверяет каждую выбранную сущность.
20. Готовая анкета администратора не изменяется действиями посетителя.
21. Профессиональный профиль не изменяется действиями посетителя.
22. Public Builder создаёт temporary configuration.
23. Temporary configuration имеет срок жизни.
24. PDF формируется сервером.
25. PDF содержит дату формирования.
26. PDF содержит ссылку на актуальный профиль.
27. QR может использоваться по настройке шаблона.
28. Поддерживается preview до PDF.
29. Desktop и mobile UX конструктора работают.
30. Типовой сценарий укладывается менее чем в три минуты.
31. Расширенный кастинговый сценарий укладывается менее чем в пять минут.
32. После PDF доступен Casting CTA.
33. Builder интегрирован с маркетинговой воронкой.
34. Аналитика не раскрывает приватные данные.
35. Администратор управляет доступными шаблонами.
36. Администратор управляет разрешением материалов.
37. Администратор может посмотреть Public Builder в режиме preview.
38. Изменение разрешения немедленно влияет на новые генерации.
39. Public Builder защищён rate limiting и server validation.
40. E2E Customer Journey Casting Director успешно проходит от landing до custom PDF и casting invitation.
